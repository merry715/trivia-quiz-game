data/questions.json을 읽고, $1 카테고리 · $2 난이도에 해당하는 퀴즈 문제 1개를 새로 만들어 추가해 줘.

## 인자 처리

$1은 카테고리, $2는 난이도를 의미해.

### 카테고리 매핑 ($1)

| 입력값 | 내부값 | ID 접두사 |
|--------|--------|----------|
| history · 역사 · 한국사 | history | hist |
| science · 과학 | science | sci |
| geography · 지리 | geography | geo |
| general · 일반 · 일반상식 | general | gen |

### 난이도 매핑 ($2)

| 입력값 | 내부값 |
|--------|--------|
| easy · 쉬움 · 쉬움 | easy |
| medium · 보통 | medium |
| hard · 어려움 | hard |

### 오류 처리

- $1이 없으면 → "사용법: /quiz-add <카테고리> <난이도> (예: /quiz-add history easy)" 안내 후 종료
- $1이 위 매핑에 없으면 → "알 수 없는 카테고리입니다. history·science·geography·general 중 하나를 입력하세요." 안내 후 종료
- $2가 없으면 → "난이도를 입력하세요. easy·medium·hard 중 하나를 선택하세요." 안내 후 종료
- $2가 위 매핑에 없으면 → "알 수 없는 난이도입니다. easy·medium·hard 중 하나를 입력하세요." 안내 후 종료

## 사전 상태 파악

data/questions.json을 읽은 뒤 아래 정보를 확인해:

1. 해당 카테고리의 기존 문제 목록과 ID 목록
2. 카테고리 전체에서 현재 사용 중인 최대 번호 → 다음 ID 결정  
   - ID 형식: `{접두사}-{2자리 숫자}` (예: hist-11, sci-12)  
   - 번호가 9 이하면 앞에 0을 붙임 (hist-09), 10 이상이면 그대로 (hist-11)
3. 해당 카테고리의 현재 난이도별 문제 수 (easy / medium / hard)

## 문제 생성 규칙

### 스키마 준수 (CLAUDE.md 기준)

```jsonc
{
  "id": "{접두사}-{2자리 번호}",
  "category": "{내부 카테고리값}",
  "difficulty": "{내부 난이도값}",
  "question": "...",      // 40자 안팎
  "choices": ["A", "B", "C", "D"],  // 4개, 각 15자 이내
  "answerIndex": 0,       // 0~3
  "explanation": "..."    // 한 줄 해설
}
```

### CLAUDE.md 교차 검증 가이드라인 체크리스트

문제를 만들 때 아래 4가지를 모두 지켜:

1. **정답이 하나뿐인가?**
   - 다른 해석이 가능하면 조건을 question에 명시한다 (예: "면적 기준", "2024년 기준")
   - 나머지 오답 보기가 정답으로 오해받을 여지가 없는지 확인한다

2. **최상급 표현에 기준이 있는가?**
   - "가장 큰", "최초의", "최대" 등을 쓸 때는 측정 기준을 question 안에 명시한다
   - 예: "면적 기준 세계에서 가장 작은", "해발고도 기준 세계에서 가장 높은"

3. **시간과 범위가 명확한가?**
   - 변할 수 있는 수치나 사실에는 시점을 명시한다
   - 지리적·분류적 범위를 한정한다 (예: "태양계에서", "한반도 역사에서")

4. **교차 검증했는가?**
   - 의심스러운 정보는 2개 이상 출처를 확인한 내용만 사용한다
   - 논란이 있는 내용은 주류 학설 기준으로 작성한다

### 보기 구성 규칙

- 정답은 4개 보기 중 임의의 위치(answerIndex 0~3)에 배치한다
  - 단, 해당 카테고리에서 정답이 특정 보기에 40% 이상 몰려 있으면 몰리지 않은 보기 위치를 우선 선택한다
- 오답 보기는 정답과 같은 분류·시대·단위 내에서 골라 변별력을 높인다
- 각 보기는 15자 이내로 작성한다

## 추가 절차

1. 위 규칙에 따라 문제 JSON 객체를 생성한다
2. data/questions.json의 `questions` 배열 맨 끝에 추가한다  
   (마지막 기존 항목의 닫는 `}` 뒤에 `,` 를 붙이고 새 객체를 삽입)
3. `node scripts/validate.js` 를 실행해 검증 결과를 확인한다

## 출력 형식

```

| 시간과 범위가 명확한가? | ✅/⚠️ | ... |

### {카테고리} 난이도 현황 (추가 후)

| 난이도 | 문제 수 |
|-------|--------|
| easy  | N개 |
| medium| N개 |
| hard  | N개 |
| 합계  | N개 |

### 검증 결과

{node scripts/validate.js 실행 결과 전체 출력}
```

체크리스트에서 ⚠️ 항목이 있으면 해당 항목 아래에 개선 이유와 수정 방향을 한 줄로 추가해.
